# @wegooli/paper-core

계약서 칸을 **같은 자로 재는** 패키지입니다.

종이 위에 칸을 어디에 둘지, 글자가 그 칸을 넘지 않으려면 얼마나 넓은지, 그 칸의 이름이 규칙에 맞는지. 이 세 가지만 계산합니다.

이 패키지는 **화면이 아닙니다.** 양식을 읽어 보여주고, 칸을 끌어 고치는 화면은 나중에 `paper-editor` 라는 다른 패키지로 나옵니다. 여기서는 종이를 그리지 않고, 화면이 무엇을 선택했는지도 기억하지 않고, 서버에 말을 걸지도 않습니다.

## 세 가지 규칙

**칸의 위치.** 화면과 저장값은 왼쪽 위가 0입니다. PDF는 왼쪽 아래가 0입니다. 그래서 PDF로 바꿀 때만 세로를 뒤집습니다. 페이지 높이에서, 위에서부터의 거리와 칸 높이를 뺍니다. 화면 위에 칸을 올릴 때는 뒤집지 않습니다. 두 번 뒤집히면 칸이 한 줄씩 점프합니다. 퍼센트가 0에서 100 밖이어도 잘라 넣지 않습니다.

**글자 폭.** 공백은 재는 쪽보다 실제로 더 넓게 찍힐 수 있습니다. 좁게 잰 값을 믿으면 글자가 옆 칸을 덮습니다. 그래서 있는 그대로 한 번 재고, 일반 공백을 `가`로 바꿔 한 번 더 재서, 더 큰 쪽을 씁니다. 폰트 파일을 넣거나 공백을 덧붙여 자리를 맞추지 않습니다. 재는 도구는 밖에서 넣습니다.

**이름표.** 칸을 가리키는 영문 이름입니다. 형식을 보고, 저장할 때는 소문자로 맞추고, 한 번 보낼 때 같은 이름으로 모이는 것은 거절합니다. `senderName`과 `sender_name`은 같은 이름입니다. 양식에 없는 이름은 목록으로 돌려줍니다. 그 목록을 보고 발송을 막을지는 부르는 쪽이 정합니다. 칸 두 개가 같은 이름인 것은 오류가 아닙니다. 두 칸에 같은 값이 들어갑니다.

## 재는 도구를 넣는 법

폭을 재는 함수 하나를 넘깁니다. 글자와 크기를 받아 숫자만 돌려주면 됩니다. 크기의 단위는 그 함수의 단위와 같아야 합니다. 서버의 pt와 화면의 px를 섞지 않습니다.

```ts
import { upperBoundTextWidth } from '@wegooli/paper-core';

const width = upperBoundTextWidth(
  (text, size) => font.widthOfTextAtSize(text, size),
  text,
  fontSize,
);
```

이 한 줄을 위해 이 패키지에 PDF 라이브러리를 넣지 않습니다. 폰트 파일도 넣지 않습니다.

## 하지 않는 일

- PDF를 만들거나 글자를 그리지 않습니다.
- 화면 상태, 버튼, 편집기를 두지 않습니다.
- 이름표가 양식에 없다고 해서 스스로 요청을 거절하지 않습니다.
- 미리 정해 둔 이름표 목록을 들고 있지 않습니다. 그 목록은 실제로 쓰는 이름과 어긋나, 발송이 통째로 실패한 적이 있습니다.
- 글자 크기의 최소 바닥을 두지 않습니다. 바닥에 걸리면 글자가 다시 칸 밖으로 나가 아랫줄을 덮습니다. 작게 찍히는 것은 눈에 보이지만, 겹친 줄은 두 값을 함께 못 읽게 합니다.

Node 22 이상.
